## Base UI APIs

- Button uses `onClick`, `disabled` and the native `render` prop. Use `nativeButton={false}` when rendering a link.
- Checkbox uses boolean `checked` and a separate `indeterminate` prop.
- Tabs, Select, Accordion, Dialog, Progress, Card, Badge and Avatar Stack use their Kalos props with Base UI composition.
- Table uses the data-driven `KalosTableProps` API, accessible table and grid roles and Base UI checkboxes. `columns` support title/text/tag/link/number/date, optional icons, widths, locked columns, fixed tag options, per-column exact-value filters, horizontal cell merging via `colSpan`, and formatting. `reorderable` adds row handles with pointer, touch and keyboard sorting; Motion handles row displacement. The action column follows the same width allocation as data columns: `rowActionsWidth` defaults to 160px; the compact previews explicitly use 84px. Row actions use 13px icons with a 16px gap. All columns align left by default. Each row needs a stable unique `id`. Editing, paste and clear respect column restrictions. Use `rows` with `onRowsChange` for controlled data; replacing an entire dataset resets editing/history by remounting with a new `key`. `editable`, `selectable` and `sortable` default to false. Place a `KalosPagination` in the optional `pagination` slot to keep it inside the Table surface. `scrollAreaProps` forwards native div attributes to the content scroller: set `style.maxHeight` to cap the data and optional summary rows. The column headers and pagination stay visible during vertical scrolling. Use a page/page-size `key` to reset scrolling while retaining pagination focus. No spreadsheet dependency is required. The row-action example composes `kalos-dialog`, `kalos-alert-dialog`, `kalos-input` and `kalos-button` for editing and confirmed deletion. Dialog and Alert Dialog accept a ReactNode `trigger` and optional `triggerProps` (`variant`, `size`, `aria-label`) for icon buttons; always name icon triggers.

```tsx
<KalosButton onClick={save} loading={saving}>保存</KalosButton>
<KalosCheckbox label="部分选择" indeterminate />
```

Documentation and source: `https://kalos-ui-six.vercel.app/components/{slug}`. Next.js, Vite and React Router share these Base UI components.

Form fields use unique `name` keys and `type`: `text`, `email`, `password`, `select`, `checkbox`, or `switch`. Add `required`, `minLength`, `items`, `hint`, `autoComplete`, and `disabled` only when needed. Errors replace hints and are linked to their controls. Cancel restores initial or last successfully saved values; changing `defaultValues` later requires remounting with a new key. Keep password values out of logs and persistent storage.

Hover Card uses Base UI PreviewCard. The child must forward its ref and event handlers. Keep essential information outside the preview. Hover and keyboard focus respect `openDelay`; touch does not open a preview. `disabled` preserves the child's own action. Empty content renders only the child.

Dropdown Menu uses Base UI Menu primitives. Items require stable `value` and `label`; `checked` defaults to an independent checkbox; items in the same group can be selected together. Use explicit `type="radio"` only for single selection within a group. Update controlled choices in `onSelect`; `keepOpen` supports repeated selections. `shortcut` only displays a hint. `trigger` is button content; use `triggerProps={{ size: "icon", "aria-label": "文件操作" }}` for icon triggers. Submenu parents only expand; actions run on leaf items.

Number Input uses Base UI NumberField. Keep `null` for an empty field. Base UI retains the second event-details argument on `onValueChange` and its native `onValueCommitted`; typing can call `onValueChange` before blur. Arrows step once, Page Up/Down use `largeStep`, Home/End reach configured bounds, and Escape restores uncommitted text. Percent formats use fractions (`0.25` → `25%`). Labels stay associated with controls without focusing them on click.

Tooltip uses Base UI Tooltip with `KalosTooltipProvider` for shared delay groups. Wrap a single ref-forwarding element in `KalosTooltip content="提示" shortcut="⌘K"`; the trigger keeps its own accessible name. Hover delay defaults to 500ms; keyboard focus opens immediately. Shortcut text does not register a shortcut. Keep content noninteractive. Table supports `variant="bordered"`; merged examples use the same grid lines. Cell text truncates at column width and uses Tooltip only on actual overflow; editing hides it.

Notification uses `KalosNotification` with a `KalosNotice[]`: stable unique `id`, required `title`, optional `badge`, `text`, `icon: ReactNode`, `pattern` (`orbit` / `grid` / `rays` / `none`), and `action` (`label`, `href`, `onClick`, `external`, `disabled`). `variant="stack"` is inline; `variant="floating"` portals to the viewport. `position` supports `top-right` (default), `bottom-right`, `top-left`, `bottom-left`; bottom positions stack upward. Only the front card is interactive and announced. Dismissed IDs stay dismissed for the mount lifetime; a new notification needs a new ID. Default examples omit badges and success-result text. Action buttons use Primary styling; `onClick` supports `void | Promise<void>`. Use KalosButton loading while pending, keep the action label visible beside its leading spinner, disable duplicate actions, and dismiss on success; keep the notice and show a retry error on rejection. Native href links keep their navigation behavior; use a button without href for async work. `onDismiss(notice)` runs for both manual closure and successful actions and can update host data. Ignore late completions after unmount or manual closure. Use Base UI buttons and Kalos tokens; keep optional copy absent and preserve the bundled affectUI MIT notice.
